# PLAN

## Phase 1 · 전용 데스크톱 앱 골격과 시각 체계 확립

**목적**  
`workbench-kit` shell에 의존하지 않는 독립 pywebview 앱을 실행하고, Downloader용 최소 화면과 Light/Dark·Codicon 시각 체계를 확립한다.

**대응 요구 ID**  
FR-22, NFR-1, NFR-2, NFR-3, NFR-8, NFR-9

**완료 조건**

- 글꼴 스택·Light/Dark 색 토큰·Codicon 패키지가 `workbench-kit` pywebview 갈래의 값과 같다.
- 화면의 모든 글자가 영어이고 아이콘은 Codicon만 쓴다.
- Windows에서 pywebview 앱 창을 실행할 수 있다.
- 기본 화면에 Toolbar, URL 입력 영역, Queue Table 영역, 하단 Status 영역이 표시된다.
- Light/Dark 두 테마를 전환했을 때 네 영역이 함께 전환된다.
- 핵심 Toolbar 아이콘이 Codicon 계열로 표시되고 의미를 확인할 수 있다.
- `workbench-kit`의 Activity Bar, Explorer, Editor shell을 포함하지 않는다.

## Phase 2 · 큐 모델과 URL 입력 흐름 완성

**목적**  
영상 URL을 붙여넣었을 때 큐에 즉시 항목이 나타나는 기본 작업 흐름과 큐 표시 모델을 만든다.

**대응 요구 ID**  
FR-1, FR-2, FR-6, FR-20, FR-21, FR-24, FR-27, FR-30, NFR-4

**완료 조건**

- 개별 YouTube 영상 URL을 붙여넣으면 큐에 행 1개가 즉시 생성된다.
- 여러 줄을 붙여넣으면 줄마다 행이 생기고, 중복 영상과 YouTube가 아닌 줄은 행 없이 상태 영역에 개수가 표시된다.
- 대기 중인 행을 삭제할 수 있다.
- 툴바에서 저장 폴더를 지정할 수 있고 초기값은 Downloads 폴더다.
- 정보 조회 전 상태와 조회 완료 후 상태를 같은 행에서 구분할 수 있다.
- 정보 조회 실패가 발생해도 다른 큐 행이 유지되고 실패 행을 식별할 수 있다.
- 하단 상태 영역이 현재 큐 개수와 주요 상태를 실제 행 상태에 맞게 표시한다.
- 정보 조회 중 기본 UI가 입력 불능 상태가 되지 않는다.

## Phase 3 · youtube-kit 정보 조회와 재생목록 전개 완성

**목적**  
로컬 `youtube-kit`의 정보 조회 결과를 큐에 연결하고, 재생목록을 영상 단위 행으로 전개한다.

**대응 요구 ID**  
FR-2, FR-3, FR-4, FR-5, FR-6, FR-25, NFR-4, NFR-6, NFR-7

**완료 조건**

- 정보 조회로 생긴 `<영상 ID>.meta.json`이 `<저장 폴더>\<영상 ID>\`에, `<list-id>.playlist.json`이 `<저장 폴더>\<list-id>\`에 저장된다.
- `watch?v=…&list=…` URL은 영상 행 1개로 처리된다.
- 정보 조회는 위쪽 행부터 동시에 최대 3개까지만 진행된다.
- 크기는 선택한 영상·음성 포맷의 크기를 모두 알 때만 표시되고 하나라도 모르면 `—`로 표시된다.

- 개별 영상 행이 자동 정보 조회 후 제목과 사용 가능한 미디어 정보를 갱신한다.
- 재생목록 URL 1개를 넣으면 접근 가능한 전체 영상이 독립된 행으로 생성된다.
- 재생목록에서 생성된 각 행이 별도 사용자 조작 없이 정보를 갱신한다.
- 조회 결과에 없는 미디어 값을 UI가 임의로 만들어 표시하지 않는다.
- 여러 재생목록 항목을 조회하는 동안 기본 UI 조작이 계속 가능하다.

## Phase 4 · 행별 포맷 선택과 큐 순서 조작 완성

**목적**  
각 영상 행에서 실제 제공되는 해상도·코덱·음성·자막을 독립적으로 선택하고 큐 순서를 조정할 수 있게 한다.

**대응 요구 ID**  
FR-7, FR-8, FR-9, FR-10, FR-11, FR-12, FR-13, FR-14, FR-26, NFR-6

**완료 조건**

- 정보 조회가 끝나면 기본 규칙에 따라 각 칸이 미리 선택되고, 규칙에 맞는 포맷이 없는 칸은 비어 있다.
- 해상도 선택지가 fps와 함께 표시되고, 해상도·fps·코덱이 같은 포맷이 여러 개면 확장자로 구분되어 모두 표시된다.
- 영상·음성·자막 칸에서 `없음`을 선택할 수 있고, 영상 칸이 선택된 행에서는 음성 `없음`을 고를 수 없다.
- 자막 목록에는 수동 자막·원어 자동 자막·선호 언어 자동 번역만 표시된다.

- 선택지가 둘 이상인 영상에서 해상도를 변경할 수 있다.
- 실제 제공되는 영상 코덱만 선택할 수 있고, 해상도와 코덱의 최종 조합이 실제 영상 포맷에 대응된다.
- 실제 제공되는 음성 트랙/포맷 중 하나를 선택할 수 있다.
- 실제 제공되는 자막 트랙과 `없음`을 선택할 수 있고 수동/자동 자막을 구분할 수 있다.
- 2개 이상의 행에 서로 다른 선택값을 설정해도 각 행의 설정이 독립적으로 유지된다.
- 3개 이상의 큐 행에서 선택 행을 위/아래로 이동했을 때 표시 순서와 작업 순서가 동일하게 변경된다.

## Phase 5 · 다운로드 실행과 진행 상태 연결

**목적**  
행에서 선택한 미디어 조건으로 실제 다운로드를 실행하고 진행·병합·완료·실패 상태를 큐에 반영한다.

**대응 요구 ID**  
FR-15, FR-16, FR-17, FR-18, FR-19, FR-20, FR-21, FR-23, FR-25, FR-27, FR-28, FR-29, FR-31, FR-32, FR-33, FR-34, NFR-5, NFR-6

**완료 조건**

- 툴바의 시작 조작으로 준비된 행이 큐 순서대로 한 행씩 다운로드된다.
- 받은 파일이 `<저장 폴더>\<영상 ID>\`에 저장된다.
- 영상 `없음`인 행은 음성만, 영상·음성 `없음`인 행은 자막만 받는다.
- 받는 중인 행 삭제와 전체 정지 후 부분 파일이 남지 않고, 완료 행을 한꺼번에 지울 수 있다.
- 이미 같은 파일이 있으면 다시 받지 않고 `이미 있음`으로 끝나며 하단 요약에서 완료로 센다.
- 설정한 컨테이너와 자막 형식으로 파일이 저장된다.
- 설정이 다음 실행 때도 유지되고 큐는 비어 있다. 다운로드 중에 닫으면 확인한다.

- 선택한 영상 포맷 ID와 음성 포맷 ID를 기준으로 영상 다운로드를 완료할 수 있다.
- 자막을 선택한 행에서는 해당 트랙의 자막 결과가 생성되고 `없음`인 행에서는 자막 다운로드가 발생하지 않는다.
- 다운로드 중 진행 상태가 행에 갱신된다.
- backend가 속도와 ETA 값을 제공하면 해당 값이 UI에 반영된다.
- 병합 단계가 발생할 때 다운로드 단계와 구분된다.
- 성공한 항목은 완료 상태, 실패한 항목은 실패 상태로 남는다.
- 다운로드 중에도 다른 큐 항목을 확인하거나 테이블을 조작할 수 있다.
- 사용자가 선택한 포맷을 이용할 수 없는 경우 임의의 다른 포맷으로 조용히 대체하지 않는다.

## Phase 6 · 실행 파일 패키징과 v0.1 통합 검증

**목적**  
실행 파일 폴더로 패키징하고, 그 실행 파일로 개별 영상과 재생목록의 전체 사용자 흐름을 통합 검증하며, 두 테마에서 compact한 Downloader 화면을 마무리한다.

**대응 요구 ID**  
FR-1 ~ FR-35 전체, NFR-1 ~ NFR-9 전체

**완료 조건**

- `npm run package:pywebview`로 실행 파일 폴더가 만들어지고, 그 폴더를 다른 경로로 옮겨도 실행된다.
- 아래 통합 검증을 실행 파일로 수행한다.

- 개별 영상 URL 입력부터 정보 조회, 행 옵션 선택, 다운로드 완료까지 한 흐름으로 검증한다.
- 재생목록 URL 입력부터 전체 행 생성, 각 행 정보 갱신, 서로 다른 행 옵션 선택, 순서 변경까지 한 흐름으로 검증한다.
- Light와 Dark 두 테마에서 툴바, 입력 영역, 테이블, 선택 상태, 진행 상태, 완료/실패 상태가 식별 가능하다.
- 큐 중심 화면에서 `BRIEF.md`의 완료 조건을 전부 직접 확인할 수 있다.
- `SPEC.md`의 모든 FR/NFR 항목에 대해 판정 방법을 수행하고 미충족 항목이 있으면 Phase 완료로 처리하지 않는다.

## 적대적 검증

**필수 통과 Phase**  
Phase 4, Phase 5, Phase 6

**Phase별 공격 초점**

| Phase | 공격 초점 |
| --- | --- |
| Phase 1 | 두 테마 중 한쪽에서만 보이지 않는 요소, `workbench-kit` shell 코드가 섞여 들어온 흔적, 화면에 남은 한국어·이모지·Codicon 아닌 아이콘, `workbench-kit`과 어긋난 글꼴·색 토큰 |
| Phase 2 | 연속 붙여넣기 중 조회 결과가 다른 행에 반영되는 경우, 중복·잘못된·빈 URL 입력, 실패 행이 하단 요약 수치에서 빠지는 경우 |
| Phase 3 | `watch?v=…&list=…` URL 처리, 접근 불가 재생목록 항목, 값이 없는 크기(`size: None`)를 0이나 추정값으로 표시하는 경우, 대량 재생목록 조회 중 UI 정지 |
| Phase 4 | 같은 해상도·코덱의 포맷이 여러 개일 때 최종 포맷 ID가 하나로 정해지는지, 해상도 변경 후 남는 무효 조합, 한 행 변경이 다른 행 선택값을 바꾸는 경우, 순서 변경 후 표시 순서와 작업 순서의 불일치 |
| Phase 5 | 선택한 포맷 ID와 실제 받은 포맷 ID의 불일치, 포맷을 이용할 수 없을 때 다른 포맷으로 조용히 대체하는 경우, 취소·정지·삭제·닫기 후 남는 부분 파일, 병합 단계와 완료 상태의 혼동, 순서 변경 후 실제 다운로드 순서의 불일치, `이미 있음`과 새로 받은 완료의 혼동, 영상 ID 폴더 밖에 생기는 파일 |
| Phase 6 | `BRIEF.md` 완료 조건과 `SPEC.md` 판정 방법을 실제로 수행했을 때 "확인했다"는 주장과 결과가 어긋나는 항목, 개발 실행에서는 되고 실행 파일에서만 깨지는 동작(경로·누락 모듈·ffmpeg 탐색) |
