# SPEC

## 기능 요구사항

### FR-1 · 영상 URL 붙여넣기

**내용**  
사용자가 YouTube 개별 영상 URL을 URL 입력 영역에 붙여넣으면 해당 영상이 큐에 추가되어야 한다.

**판정 방법**  
유효한 개별 영상 URL 1개를 클립보드에서 붙여넣었을 때 큐에 해당 입력을 나타내는 행 1개가 생성되는지 확인한다.

---

### FR-2 · 큐 선등록 후 정보 자동 갱신

**내용**  
영상 URL은 정보 조회가 끝나기 전에 큐에 먼저 나타나야 하며, 정보 조회 결과가 도착하면 같은 행의 표시 정보와 선택 가능한 항목이 자동 갱신되어야 한다.

**판정 방법**  
네트워크 조회가 필요한 영상 URL을 붙여넣고, 초기 상태의 행이 먼저 생성된 뒤 별도의 사용자 조작 없이 제목 및 미디어 선택 정보가 같은 행에 채워지는지 확인한다.

---

### FR-3 · 재생목록 URL 인식

**내용**  
사용자가 YouTube 재생목록 URL을 붙여넣으면 개별 영상 URL과 구분해 재생목록으로 처리해야 한다.

**판정 방법**  
영상이 2개 이상 포함된 재생목록 URL을 붙여넣었을 때 하나의 영상 행으로 처리되지 않고 재생목록의 영상 목록을 기준으로 큐가 구성되는지 확인한다. 영상 ID와 재생목록 ID가 함께 있는 `watch?v=…&list=…` URL은 영상 행 1개만 생성되는지 확인한다.

---

### FR-4 · 재생목록 전체 영상 큐 추가

**내용**  
재생목록 URL을 입력하면 재생목록에 포함된 전체 영상이 각각 독립된 큐 행으로 추가되어야 한다.

**판정 방법**  
항목 수를 확인할 수 있는 재생목록을 입력하고, 접근 가능한 재생목록 항목 수와 생성된 큐 행 수가 일치하는지 확인한다. 접근 불가 항목이 있으면 해당 차이가 오류 상태로 식별 가능한지 함께 확인한다.

---

### FR-5 · 재생목록 항목별 자동 정보 조회

**내용**  
재생목록에서 생성된 각 영상 행은 별도의 추가 조작 없이 해당 영상의 정보를 조회하고 갱신해야 한다.

**판정 방법**  
재생목록을 추가한 뒤 각 행이 사용자 개입 없이 초기/조회 상태에서 정보 준비 상태로 변경되고 제목과 미디어 선택 정보가 채워지는지 확인한다.

---

### FR-6 · 큐 기본 정보 표시

**내용**  
각 큐 행은 최소한 영상 식별 정보, 제목, 파일 크기 정보가 제공되는 경우의 크기, 선택된 해상도, 영상 코덱, 음성, 자막, 다운로드 상태 및 진행 상태를 확인할 수 있어야 한다.

**판정 방법**  
정보 조회가 완료된 영상 1개를 기준으로 해당 항목들이 한 행에서 확인 가능한지 검사한다. 원본 정보에서 값을 제공하지 않는 항목은 임의의 값을 만들어 표시하지 않고 알 수 없음 상태로 구분되는지 확인한다. 크기는 선택한 영상·음성 포맷의 크기를 모두 알 때만 합계로 표시되고, 하나라도 모르면 `—`로 표시되며, 다운로드가 시작되면 진행 이벤트의 전체 바이트 값으로 채워지는지 확인한다.

---

### FR-7 · 해상도 선택

**내용**  
각 영상 행에서 해당 영상이 실제로 제공하는 영상 포맷을 기준으로 해상도를 선택할 수 있어야 한다. 해상도 선택지는 `1080p60`처럼 fps와 함께 표시하며, `없음`도 선택할 수 있다.

**판정 방법**  
둘 이상의 해상도를 제공하는 영상을 추가하고, 행의 해상도 선택 목록에 조회 결과와 대응되는 선택지가 fps와 함께 표시되며 다른 해상도와 `없음`을 선택할 수 있는지 확인한다.

---

### FR-8 · 영상 코덱 선택

**내용**  
각 영상 행에서 해당 영상과 선택 조건에서 실제 사용 가능한 영상 코덱을 선택할 수 있어야 한다.

**판정 방법**  
둘 이상의 영상 코덱 선택지가 있는 영상을 추가하고, 선택 목록에서 실제 제공되는 코덱 중 하나를 선택할 수 있는지 확인한다. 조회 결과에 없는 코덱이 선택 가능한 값으로 나타나지 않는지 확인한다.

---

### FR-9 · 해상도와 코덱 선택의 유효성 유지

**내용**  
해상도와 영상 코덱의 조합은 해당 영상의 실제 포맷 목록으로 표현 가능한 조합이어야 한다.

**판정 방법**  
해상도 변경 후 현재 코덱이 그 해상도에서 제공되지 않는 경우 유효하지 않은 조합이 그대로 다운로드 설정으로 남지 않는지 확인한다. 최종 선택이 실제 영상 포맷 ID 하나로 대응되는지 확인한다. 해상도·fps·코덱이 같은 포맷이 여러 개인 영상에서는 선택지가 `1080p60 · mp4` / `1080p60 · webm`처럼 구분되어 모두 표시되고, 앱이 그중 하나를 자동으로 고르지 않는지 확인한다.

---

### FR-10 · 음성 선택

**내용**  
각 영상 행에서 해당 영상이 제공하는 음성 트랙/포맷을 선택할 수 있어야 하며, `없음`도 선택할 수 있어야 한다.

**판정 방법**  
둘 이상의 음성 선택지가 있는 영상을 추가하고, 조회된 음성 항목 중 하나와 `없음`을 선택할 수 있으며 최종 선택이 실제 음성 포맷 ID에 대응되는지 확인한다.

---

### FR-11 · 자막 선택

**내용**  
각 영상 행에서 해당 영상이 제공하는 자막 트랙을 선택할 수 있어야 하며, 수동 자막과 자동 자막이 구분 가능한 경우 그 차이를 식별할 수 있어야 한다. 자막을 받지 않는 선택도 가능해야 한다. 선택 목록에는 수동 자막, 원어 자동 자막, 선호 언어(초기값 `ko`, 설정에서 변경)의 자동 번역 자막만 표시한다.

**판정 방법**  
수동/자동 자막 중 하나 이상을 제공하는 영상을 추가하고, 제공되는 자막 트랙과 `없음`을 선택할 수 있는지 확인한다. 선택한 자막이 실제 자막 트랙 ID와 대응되는지 확인한다. 자동 번역 트랙이 많은 영상에서 목록에 수동 자막·원어 자동 자막·선호 언어 자동 번역 외의 트랙이 나타나지 않는지 확인한다.

---

### FR-12 · 행별 선택 독립성

**내용**  
각 큐 행의 해상도·코덱·음성·자막 선택은 다른 행의 선택과 독립적으로 유지되어야 한다.

**판정 방법**  
영상 2개 이상을 큐에 추가한 뒤 서로 다른 옵션을 선택하고, 한 행의 값을 변경해도 다른 행의 선택값이 바뀌지 않는지 확인한다.

---

### FR-13 · 큐 행 위로 이동

**내용**  
선택한 큐 행을 현재 위치보다 한 단계 위로 이동할 수 있어야 한다.

**판정 방법**  
3개 이상의 행을 만든 뒤 중간 행을 선택해 위로 이동시키고, 표시 순서와 내부 작업 순서가 함께 변경되는지 확인한다.

---

### FR-14 · 큐 행 아래로 이동

**내용**  
선택한 큐 행을 현재 위치보다 한 단계 아래로 이동할 수 있어야 한다.

**판정 방법**  
3개 이상의 행을 만든 뒤 중간 행을 선택해 아래로 이동시키고, 표시 순서와 내부 작업 순서가 함께 변경되는지 확인한다.

---

### FR-15 · 선택 설정으로 영상 다운로드

**내용**  
큐 행에서 선택한 영상 포맷과 음성 포맷을 기준으로 해당 영상을 다운로드할 수 있어야 한다. 영상이 `없음`이면 음성만, 영상과 음성이 모두 `없음`이면 자막만 받는다. 영상 칸이 선택되어 있으면 음성 칸의 `없음`은 고를 수 없다.

**판정 방법**  
영상 칸을 선택한 행에서 음성 칸의 `없음`을 고를 수 없는지 확인한다. 
다운로드 가능한 영상 1개에서 특정 해상도/코덱과 음성을 선택해 실행하고, 완료된 결과가 선택에 대응되는 영상 포맷 ID와 음성 포맷 ID를 사용했는지 확인한다. 영상 `없음`인 행에서는 음성 파일만, 영상·음성 `없음`에 자막을 고른 행에서는 자막 파일만 생성되는지 확인한다.

---

### FR-16 · 선택 자막 다운로드

**내용**  
행에서 자막 트랙을 선택한 경우 해당 자막을 다운로드 대상으로 처리할 수 있어야 한다. `없음`을 선택한 경우 자막 다운로드를 요구하지 않아야 한다.

**판정 방법**  
자막 트랙을 선택한 영상과 `없음`을 선택한 영상을 각각 실행하고, 전자에서는 선택한 트랙에 해당하는 자막 결과가 생성되고 후자에서는 자막 다운로드가 발생하지 않는지 확인한다.

---

### FR-17 · 다운로드 진행 상태 표시

**내용**  
다운로드 중인 행은 다운로드 단계와 진행률을 확인할 수 있어야 하며, 제공되는 경우 속도와 남은 시간 정보도 표시할 수 있어야 한다.

**판정 방법**  
다운로드가 즉시 끝나지 않는 영상을 실행하고, 작업 중 해당 행에서 진행 상태가 갱신되는지 확인한다. backend가 속도/남은 시간 값을 제공한 경우 UI에 반영되는지 확인한다.

---

### FR-18 · 병합 단계 표시

**내용**  
영상과 음성 다운로드 후 병합 단계가 발생하면 다운로드 단계와 구분되는 상태로 표시되어야 한다.

**판정 방법**  
영상·음성 병합이 필요한 항목을 다운로드하고, backend가 병합 단계를 알린 시점에 해당 행의 상태가 단순 다운로드 중과 구분되는지 확인한다.

---

### FR-19 · 완료 상태 표시

**내용**  
정상적으로 끝난 큐 항목은 완료 상태로 명확히 표시되어야 한다.

**판정 방법**  
영상 1개의 다운로드를 완료하고, 해당 행의 상태가 완료로 바뀌며 더 이상 진행 중으로 표시되지 않는지 확인한다.

---

### FR-20 · 실패 상태 표시

**내용**  
정보 조회 또는 다운로드가 실패한 큐 항목은 다른 항목과 구분되는 실패 상태를 표시해야 하며, 실패가 전체 큐의 표시를 사라지게 해서는 안 된다.

**판정 방법**  
접근 불가 또는 잘못된 영상을 포함시켜 실패를 발생시키고, 해당 행만 실패 상태로 확인 가능하며 기존의 다른 큐 행이 유지되는지 확인한다.

---

### FR-21 · 하단 큐 상태 요약

**내용**  
화면 하단에서 현재 큐의 전체 개수와 주요 진행 상태를 요약해 확인할 수 있어야 한다.

**판정 방법**  
대기/진행/완료 상태가 섞인 큐를 만들고, 하단 요약 값이 실제 큐 상태와 일치하는지 확인한다.

---

### FR-22 · Light/Dark 테마 전환

**내용**  
사용자는 Light와 Dark 두 테마 사이를 전환할 수 있어야 한다.

**판정 방법**  
앱 실행 중 테마 전환 조작을 수행하고, 툴바·입력 영역·테이블·상태 영역이 동일 테마 체계로 함께 변경되는지 확인한다.

---

### FR-23 · 전체 시작과 큐 순서대로 순차 다운로드

**내용**  
툴바의 시작 조작 하나로 다운로드를 시작하며, 받을 준비가 된 행을 큐의 위에서부터 한 번에 하나씩 받아야 한다.

**판정 방법**  
준비된 행 3개 이상을 만든 뒤 순서를 바꾸고 시작해, 행이 바뀐 큐 순서대로 하나씩 진행되며 동시에 두 행 이상이 다운로드 중으로 표시되지 않는지 확인한다.

---

### FR-24 · 저장 폴더 지정

**내용**  
저장 폴더는 앱 전체에 하나이며 툴바에서 바꿀 수 있어야 한다. 초기값은 사용자의 Downloads 폴더다.

**판정 방법**  
첫 실행에서 저장 폴더가 Downloads인지 확인하고, 툴바에서 다른 폴더로 바꾼 뒤 받은 파일이 바꾼 폴더 아래에 생성되는지 확인한다.

---

### FR-25 · 영상 ID별 저장 폴더

**내용**  
영상 하나의 meta 파일과 받은 영상·음성·자막 파일은 `<저장 폴더>\<영상 ID>\`에 저장되어야 한다. 재생목록에서 펼친 영상도 같은 위치에 저장하고, 재생목록의 `<list-id>.playlist.json`은 `<저장 폴더>\<list-id>\`에 저장한다.

**판정 방법**  
개별 영상 1개와 재생목록 1개를 받은 뒤, 각 영상의 `<영상 ID>.meta.json`과 미디어·자막 파일이 `<저장 폴더>\<영상 ID>\`에 있고, `<list-id>.playlist.json`이 `<저장 폴더>\<list-id>\`에 있으며, 저장 폴더 바로 아래에 다른 파일이 생기지 않는지 확인한다.

---

### FR-26 · 기본 규칙으로 미리 선택

**내용**  
정보 조회가 끝나면 설정의 기본 규칙에 따라 해상도·코덱·음성·자막이 미리 선택되어야 한다. 규칙에 맞는 포맷이 없으면 그 칸은 비어 있어야 한다. 기본 규칙의 초기값은 영상 1080p 이하 중 최고 해상도·avc1·높은 fps, 음성은 원본 언어이고 drc가 아닌 m4a 중 최고 음질, 자막 없음이다. 기본 규칙은 설정에서 바꿀 수 있다.

**판정 방법**  
초기 규칙으로 영상 1개를 추가해 각 칸이 규칙에 맞는 포맷으로 선택되는지 확인한다. avc1 포맷이 없는 영상에서 코덱 칸이 다른 코덱으로 채워지지 않고 비어 있는지 확인한다. 설정에서 규칙을 바꾼 뒤 새로 추가한 행에 바뀐 규칙이 적용되는지 확인한다.

---

### FR-27 · 행 삭제

**내용**  
선택한 행을 큐에서 삭제할 수 있어야 하며, 받는 중인 행이면 취소한 뒤 삭제해야 한다.

**판정 방법**  
대기 중인 행과 받는 중인 행을 각각 삭제하고, 행이 큐에서 사라지며 받는 중이던 행의 부분 파일이 남지 않는지 확인한다.

---

### FR-28 · 전체 정지

**내용**  
툴바의 정지 조작으로 다운로드를 멈출 수 있어야 하며, 받던 행은 취소되어야 한다.

**판정 방법**  
다운로드 중 정지하고, 받던 행이 취소 상태가 되며 부분 파일이 남지 않고 다음 행이 시작되지 않는지 확인한다.

---

### FR-29 · 완료 행 지우기

**내용**  
완료된 행을 한꺼번에 큐에서 지울 수 있어야 한다.

**판정 방법**  
완료·대기·실패 행이 섞인 큐에서 완료 행 지우기를 실행하고, 완료 행만 사라지고 나머지는 순서대로 남는지 확인한다.

---

### FR-30 · 여러 줄 붙여넣기와 중복·잘못된 입력 처리

**내용**  
붙여넣은 내용의 줄마다 URL 하나로 보고 모두 추가해야 한다. 큐에 이미 있는 영상 ID는 추가하지 않고 상태 영역에 건너뛴 개수를 알려야 한다. YouTube URL이 아닌 줄은 행을 만들지 않고 상태 영역에 알려야 한다.

**판정 방법**  
새 URL 2개, 이미 큐에 있는 URL 1개, YouTube가 아닌 줄 1개를 한 번에 붙여넣고, 행이 2개만 추가되며 상태 영역에 중복 1개와 잘못된 입력 1개가 표시되는지 확인한다.

---

### FR-31 · 이미 받은 파일 처리

**내용**  
같은 파일이 이미 있어 다시 받지 않은 행은 완료와 구분되는 `이미 있음` 상태로 끝나야 하며, 하단 요약에서는 완료로 센다.

**판정 방법**  
같은 영상을 같은 포맷으로 두 번 받아, 두 번째 행이 다시 받지 않고 `이미 있음`으로 표시되며 하단 요약의 완료 수에 포함되는지 확인한다.

---

### FR-32 · 설정 유지

**내용**  
테마·저장 폴더·기본 규칙·선호 언어·컨테이너·자막 형식·창 크기는 다음 실행 때도 유지되어야 하며, 큐는 비운 채로 시작해야 한다.

**판정 방법**  
각 설정을 초기값과 다르게 바꾸고 행을 추가한 뒤 앱을 다시 실행해, 설정이 유지되고 큐가 비어 있는지 확인한다.

---

### FR-33 · 다운로드 중 닫기 확인

**내용**  
다운로드 중에 앱을 닫으면 닫을지 확인해야 하며, 닫으면 받던 작업을 취소해야 한다.

**판정 방법**  
다운로드 중 창을 닫아 확인이 표시되는지 보고, 닫기를 선택했을 때 부분 파일이 남지 않는지, 취소를 선택했을 때 다운로드가 계속되는지 확인한다.

---

### FR-34 · 컨테이너와 자막 형식 설정

**내용**  
영상 컨테이너(초기값 자동: mp4에 들어가면 mp4, 아니면 mkv)와 자막 형식(초기값 srt)을 앱 전체 설정에서 바꿀 수 있어야 한다.

**판정 방법**  
초기값으로 받은 파일의 확장자를 확인하고, 설정에서 컨테이너를 mkv로, 자막 형식을 vtt로 바꾼 뒤 받은 파일의 확장자가 바뀌는지 확인한다.

---

### FR-35 · 실행 파일로 실행

**내용**  
패키징한 실행 파일 폴더로 앱을 실행할 수 있어야 한다.

**판정 방법**  
패키징 명령으로 만든 실행 파일 폴더를 개발 환경 밖의 다른 경로로 옮겨 실행하고, 개별 영상 1개의 추가·정보 조회·다운로드가 완료되는지 확인한다.

## 비기능 요구사항

### NFR-1 · compact desktop UI

**내용**  
주요 정보와 조작은 불필요한 카드·패널을 반복하지 않는 compact한 데스크톱 UI로 제공되어야 한다.

**판정 방법**  
기본 화면에서 URL 입력, 큐 테이블, 주요 다운로드 조작, 상태 요약을 별도 화면 전환 없이 확인할 수 있는지 검토한다.

---

### NFR-2 · 일관된 Light/Dark 가독성

**내용**  
Light와 Dark 모두에서 텍스트, 선택 상태, 입력 컨트롤, 테이블 경계, 진행 상태를 구분할 수 있어야 한다.

**판정 방법**  
두 테마 각각에서 기본/hover/selected/disabled/failed/completed 상태를 육안으로 확인하고 텍스트와 배경이 서로 구분되는지 검토한다.

---

### NFR-3 · 아이콘 스타일 일관성

**내용**  
툴바의 핵심 조작 아이콘은 동일한 Codicon 계열 시각 스타일을 사용해야 한다.

**판정 방법**  
툴바를 검사해 서로 다른 외부 아이콘 스타일이 혼용되지 않고, 각 아이콘 조작의 의미를 툴팁 또는 주변 맥락으로 확인할 수 있는지 검토한다.

---

### NFR-4 · 정보 조회 중 UI 응답 유지

**내용**  
영상 또는 재생목록 정보를 조회하는 동안 앱의 기본 화면이 멈춘 상태가 되어서는 안 된다.

**판정 방법**  
여러 영상이 포함된 재생목록을 추가한 직후 다른 큐 행 선택, 테마 전환 또는 허용된 기본 UI 조작이 계속 가능한지 확인한다.

---

### NFR-5 · 다운로드 중 UI 응답 유지

**내용**  
다운로드가 진행되는 동안 사용자는 다른 큐 항목의 정보를 확인하고 선택 상태를 볼 수 있어야 한다.

**판정 방법**  
다운로드 중 다른 행을 선택하거나 테이블을 스크롤했을 때 앱이 입력 불능 상태가 되지 않는지 확인한다.

---

### NFR-6 · backend 값의 임의 대체 금지

**내용**  
조회 결과에 없는 해상도·코덱·음성·자막을 UI가 존재하는 것처럼 만들어 선택시키거나, 사용자가 지정한 항목이 없을 때 임의의 다른 포맷으로 조용히 대체해서는 안 된다.

**판정 방법**  
존재하지 않는 선택 조합 또는 더 이상 이용할 수 없는 포맷 상황을 만들고, 임의 대체 다운로드가 아니라 선택 불가 또는 실패 상태로 식별되는지 확인한다.

---

### NFR-7 · 정보 조회 동시 수

**내용**  
정보 조회는 큐 위쪽 행부터 동시에 최대 3개까지만 진행해야 한다.

**판정 방법**  
영상 10개 이상의 재생목록을 추가하고, 조회 중인 행이 동시에 3개를 넘지 않으며 위쪽 행부터 조회되는지 확인한다.

---

### NFR-8 · UI 표기는 영어와 Codicon만

**내용**  
UI에 보이는 모든 글자는 영어여야 하며, 아이콘은 Codicon만 사용해야 한다. YouTube에서 받은 값(영상 제목 등)은 예외로 원문 그대로 표시한다.

**판정 방법**  
화면 소스(`src/`의 TS·HTML·CSS)와 Python이 화면으로 보내는 문자열에 한글 문자(U+AC00–U+D7A3, U+3131–U+318E)가 없는지 검색한다. 화면의 아이콘 요소가 모두 Codicon 클래스(`codicon codicon-*`)이며 이모지·이미지 아이콘이 없는지 검색한다. 한글 제목 영상을 넣었을 때 제목만 한글로 보이는지 확인한다.

---

### NFR-9 · workbench-kit pywebview 갈래와 같은 시각 체계

**내용**  
글꼴 스택, 공통 스타일 토큰, Light/Dark 테마 색, Codicon 패키지는 `workbench-kit` pywebview 갈래의 값과 같아야 한다.

**판정 방법**  
이 앱의 글꼴 스택과 Light/Dark 색 토큰 값을 `workbench-kit` `src/style.css`의 글꼴 스택 및 `[data-theme="light"]`·`[data-theme="dark"]` 블록 값과 대조해 차이가 없는지 확인한다. `@vscode/codicons` 패키지 버전이 같은지 확인한다. 차이가 있으면 그 항목과 이유가 `PROGRESS.md`에 기록되어 있어야 한다.

## 제약사항

- 대상은 Windows 데스크톱 애플리케이션이다.
- 앱 shell은 `pywebview`를 사용한다.
- Python backend의 YouTube 처리 기능은 로컬 `youtube-kit`을 재사용한다.
- 현재 `youtube-kit`이 요구하는 Python 3.11 이상 환경을 기준으로 한다.
- 영상과 음성 병합 기능에는 `ffmpeg`가 필요하며 실행 환경에서 사용할 수 있어야 한다.
- 로컬 `workbench-kit`은 Light/Dark 테마, Codicon, spacing 및 pywebview UI 연결 방식의 참고 자료로만 사용한다.
- `workbench-kit`의 shell 또는 공통 기능을 애플리케이션 의존성으로 가져오지 않는다.
- 글꼴·스타일·테마·아이콘은 `workbench-kit`의 pywebview 갈래를 참조해 같은 값으로 맞춘다(D-30). gray 테마는 가져오지 않는다.
- UI 글자는 영어, 아이콘은 Codicon만 쓴다(D-29).
- 빌드·실행·패키징은 `workbench-kit`의 pywebview 갈래 방식을 따른다 — Vite + TypeScript 화면 빌드, `npm run start:pywebview` 개발 실행, `npm run package:pywebview` PyInstaller 실행 파일 폴더.
- 개발 중에는 로컬 `youtube-kit`을 editable 설치로 참조하고, 실행 파일에는 `youtube-kit`과 `yt-dlp`를 함께 묶는다.
- `ffmpeg`는 실행 파일에 넣지 않고 PATH에서 찾는다.
- `youtube-kit`에는 영상만(음성 없음) 받는 함수가 없다. 따라서 영상 칸이 선택된 행에서는 음성 `없음`을 막는다(D-17).
- 프로젝트 문서와 진행 방식은 로컬 `project-workflow`의 현재 스키마를 따른다.
- 구현 시 `youtube-kit`, `workbench-kit`, `project-workflow`는 로컬 저장소의 실제 코드를 직접 확인해 현재 상태와 불일치하는 추정을 피한다.
